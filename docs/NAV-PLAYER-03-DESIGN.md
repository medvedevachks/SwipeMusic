## 2. Анализ текущих экранов

### Общая оболочка

Фиксированный каркас `app-shell`: шапка → прокручиваемый `main` → док (`BottomPlayer` + `BottomNav`).  
Тема уже задаёт идентичность: **Syne** + teal accent (`#0f766e` / `#1f8f84`), светлый `#f3f5f7` / тёмный `#10161b`. Это стоит сохранить как бренд-базу, а не заменять «чужим» look.

### Замер chrome на 1024×600 (реальный CDP)

| Зона | Высота | Доля viewport |
|------|--------|----------------|
| Шапка | ~65 px | **~11%** |
| Основной контент (`main`) | ~391 px | **~65%** |
| Мини-плеер | ~95 px | **~16%** |
| Нижняя навигация | ~49 px | **~8%** |
| Док суммарно | ~144 px | **~24%** |

На магнитоле почти **четверть** экрана занята доком, ещё **11%** — шапкой. Полезная площадь контента ≈ 65%. На колоде/волне это критично: карточка и подсказки конкурируют с дублирующим транспортом мини-плеера.

### 390×844 — телефон

- Карточка свайпа читается, но Play на карточке **дублирует** Play мини-плеера.
- Мини-плеер сильно режет метаданные (`Ис…` / `Зем…`) — обложка и название не «держат» иерархию.
- Библиотека: нижние пункты каталогов частично перекрываются доком.
- Fullscreen: обложка доминирует; транспорт доступен; **время прогресса дублируется** (на баре и под ним).
- Поиск в DEV: блок «Dev · Search Log» съедает первый экран — результаты уходят вниз (для прод-концепции: лог не должен быть частью пользовательской иерархии).

### 1024×600 — магнитола

- Горизонтальный fullscreen уже раскладывает art | meta+transport — направление верное.
- Много «воздуха» справа/снизу при том, что док снизу всё равно тяжёлый на не-fullscreen экранах.
- Мини-плеер на широкой ширине показывает shuffle/repeat/volume/speed — **плотность выше, чем нужно** для «сейчас играет».
- Навигация 4 таба внизу на горизонтали ок по паттерну, но вместе с толстым мини-плеером давит на списки.

### 1366×768 — ПК

- Контент узкий (`app-main-frame` ≤ 42rem) — много боковых полей. Для ПК это выглядит «мобильным сайтом в центре», а не desktop music surface.
- Мини-плеер разворачивает полный набор контролов — удобно мышью, но визуально шумно рядом с карточкой/списком.

## 3. Конкретные UX-проблемы

1. **Дублирование транспорта** — Play/Pause + progress на карточке свайпа и в мини-плеере одновременно.
2. **Толстый мини-плеер** — на телефоне режет title/artist; на car/PC несёт secondary controls (speed, volume strip, shuffle/repeat), которые не обязаны быть always-on.
3. **Chrome budget на 1024×600** — шапка + док ≈ 35%; контент голодает.
4. **Слабый акцент на обложке в списках** — в каталоге/очереди обложки мелкие, вторичные бейджи источника конкурируют с названием.
5. **Fullscreen: вторичное на первом плане** — бейдж источника, `stream`, подпись сессии «Сейчас играет» рядом с названием; дубль timestamps.
6. **Шапка малополезная на car** — бренд + theme toggle + профиль постоянно занимают ~65 px при малой высоте.
7. **ПК не использует ширину** — один узкий столбец; нет «сцены» для плеера/обложки.
8. **Перекрытие списков доком** — библиотека/каталог: последние строки под мини-плеером.
9. **DEV-шум в поиске** — search log как primary content (не прод-UX, но искажает аудит «полезной площади»).
10. **Нет явной иерархии «жест свайпа vs глобальный плеер»** — пользователь видит два «центра управления» на одном экране.

## 4. Дизайн-концепция: единый подход

### Позиционирование

**Swipe Music = жест оценки + честный глобальный плеер.**  
Идентичность: спокойный «studio light / night cabin» (текущие CSS variables), акцент teal, display Syne. Не клонировать Spotify/ЯМ: сохранить свайп-колоду как уникальный жест; плеер — ясный и компактный, без маркетинговых chips и коллажей.

### Принципы

1. **Одна primary surface на экран** — либо колода/список, либо fullscreen; мини-плеер — компактный мост, не второй пульт.
2. **Обложка + композиция** — крупнейшие визуальные якоря; источник и техника — вторичны.
3. **Транспорт понятен за 0.5 с** — Prev / Play / Next всегда; shuffle/repeat — рядом, но не спорят с Play.
4. **Like и каталог** — жесты продукта: на колоде через свайп; в fullscreen — явный primary row; в мини — только через tap → full (или long-press later).
5. **Компактная навигация** — 4 таба остаются; высота дока снижается.
6. **Адаптив по высоте, не только по ширине** — отдельные режимы `phone` / `car-short` / `desktop`.
7. **Тема не ломается** — только перестановка иерархии и плотности; без новой палитры.

### Визуальный язык (без смены темы)

- Поверхности: `--color-surface` + лёгкий `deck-panel` blur только у мини/fullscreen chrome.
- Радиусы: сохранить мягкие, но **убрать «карточки ради карточек»** в списках там, где строка и так читается.
- Типографика: title semibold truncate 1 line; artist muted; source — micro / menu.
- Motion (на 03B): короткое появление fullscreen, сдвиг progress; без glow/noise.

## 5. Плеер — иерархия «сразу / позже»

### Видно сразу (primary)

| Элемент | Мини | Fullscreen |
|---------|------|------------|
| Обложка | да (малая) | да (доминанта) |
| Название + исполнитель | да | да |
| Прогресс | тонкая полоса | полоса + одно время |
| Play/Pause | да | да (крупнее) |
| Next / Previous | да | да |
| Like | нет (→ full) | да |
| Каталогизация | нет (→ full) | да |

### Дополнительные действия (secondary / меню «⋯»)

- Источник и бейдж каталога-источника  
- Переключение альтернативной копии  
- Скорость воспроизведения  
- Громкость (на телефоне; на car/PC можно оставить inline в expanded mini)  
- Подробности сессии («Сейчас играет», длинные подписи)  
- Shuffle / Repeat на **телефоне в мини** — в ⋯ или только в fullscreen; на car/PC mini expanded — допустимы inline  

**Функции не удаляются** — только уходят с первого визуального ряда.

## 6. Целевая структура мини-плеера

### Режим A — Compact (default phone, и car при нехватке высоты)

```
[ cover 40 ]  Title                 [ ⏮ ][ ▶/❚❚ ][ ⏭ ]
              Artist · (optional)   ──────── progress ────
```

- Высота цели: **≤ 64–72 px** (+ safe area), без второго ряда кнопок.
- Tap по meta/cover → fullscreen.
- Shuffle / Repeat / Volume / Speed / Source → ⋯ или fullscreen.

### Режим B — Expanded (ширина ≥ ~900 px и высота ≥ ~700 px)

```
[ cover ] Title / Artist     [ ⇄ ][ ⏮ ][ ▶ ][ ⏭ ][ ⟳ ]   [ vol ] [ ⋯ ]
          ──────── progress ────────────────────────────────
```

- Один ряд транспорта; speed/source только в ⋯.
- Не дублировать progress, если на текущем экране уже есть progress карточки (свайпы): на Home в режиме Playing на карточке — **мини без seek**, только transport+meta (опциональное правило 03B).

### Цель по chrome (1024×600)

- Мини compact: ~56–64 px  
- Nav: ~44–48 px  
- Док суммарно: **≤ ~110 px (~18%)** вместо текущих ~24%  
- Высвобождение ~30–40 px для колоды/списка

## 7. Целевая структура полноэкранного плеера

### Phone 390×844 (портрет)

```
[ ✕ ]     Session (коротко)      [ ⋯ ]
          ┌─────────────────┐
          │     COVER       │   ← доминирует
          └─────────────────┘
               Title
               Artist
          ─── progress · time ───     ← время один раз
     [ ⇄ ] [ ⏮ ] [ ▶❚❚ ] [ ⏭ ] [ ⟳ ]
     [ ♥ ]     [ В каталог ]     [ ≡ queue ]
```

- Session label — одна короткая строка (без «Сейчас играет» как второго заголовка).  
- Source / stream / alternatives — в ⋯.  
- Like + каталог + queue — нижний action row (уже близко к текущему; усилить контраст Like).

### Car 1024×600 (landscape short)

```
[ ✕ ]  Session                    [ ⋯ ]
┌──────────┬──────────────────────────────┐
│          │  Title                       │
│  COVER   │  Artist                      │
│          │  progress + time             │
│          │  [⇄][⏮][▶][⏭][⟳]            │
│          │  [♥] [В каталог] [queue]     │
└──────────┴──────────────────────────────┘
```

- Весь primary transport **без прокрутки** (уже заложено в CSS landscape) — сохранить как hard requirement.  
- Убрать визуальный дубль timestamps.  
- Не показывать нижний app-dock под overlay (уже overlay z-60) — ок.

### Desktop 1366×768

- Та же схема, что car, но шире art; опционально правая колонка «очередь / up next» в 03B+ (не обязательно в первом визуальном проходе).

## 8. Адаптация экранов продукта (не только плеер)

### Свайпы

- Карточка = жест и оценка; Play на карточке оставляем как **локальный старт этой композиции**, но визуально secondary к глобальному транспорту (меньший control или только tap по обложке → play, без гигантского круга-дубля).  
- Подписи ←→↑↓ — компактнее на car; не отнимать ширину stage.

### Волна / Поиск / Библиотека / Каталог

- Списки: title+artist primary; source micro; play row-control 44×44.  
- Библиотека: уменьшить вертикальный «героизм» заголовка+подзаголовка на car.  
- ПК: рассмотреть `max-width` frame > 42rem для library/search **или** двухколоночный browse (03B низкий приоритет).

### Очередь

- Текущий трек выделен; остальные — плотные строки; связь с fullscreen queue button без нового chrome.
